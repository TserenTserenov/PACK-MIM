# MIM.R.001 — Наставник

> Зонтичная роль с двумя режимами: (1) плановый разбор в группе через фасилитацию, (2) always-on диагноз+рекомендация 1:1 в чате через связку ролей. Общее в обоих режимах: опытный взгляд видит то, что не видит нетренированный, и указывает человеку путь вперёд.

## Summary

Наставник — ключевая роль в МИМ, зонтик над двумя разными по методу и формату режимами работы:

- **Режим 1 (плановый, групповой)** — опытный специалист ведёт разборы (MIM.FMT.004), даёт обратную связь и производит замер квалификации (MIM.WP.003) в практикумах и резидентурах. Метод — фасилитация. См. §Режим 1 ниже.
- **Режим 2 (always-on, 1:1)** — синхронный ответ в чате на свободное описание человеком своего текущего состояния: диагноз + рекомендация + мотивация + при необходимости предметное объяснение. Метод — маршрутизация между ролями-компонентами связки. См. §Режим 2 ниже.

Без наставника (в любом режиме) — заучивание ошибок (MIM.FM.002).

## Режим 1 — Плановый разбор (группа)

## Функции

1. **Ведёт разборы** (MIM.FMT.004) — review промежуточных и конечных результатов
2. **Даёт обратную связь** — указывает на ошибки и направления улучшения
3. **Замеряет квалификацию** (MIM.WP.003) — фиксирует уровень при каждом разборе
4. **Корректирует тренировку** — в практикуме (MIM.FMT.002) направляет упражнения
5. **Сопровождает шедевр** — в резидентуре (MIM.FMT.003) ведёт review работы
6. **Фасилитирует** — создаёт условия для самостоятельного открытия и интеграции знаний через вопросы, задачи, дискуссии и рефлексию (MIM.D.007)

## Методическая основа: фасилитация

Наставник не передаёт знание напрямую (для этого Докладчик, MIM.R.002), а направляет процесс:

- **Постановка провокативных вопросов** — помогает ученику самому увидеть ошибку
- **Организация групповой работы и дискуссий** — равное участие, фокус
- **Организация рефлексии** — осмысление опыта после разбора
- **Модерация обсуждений** — удерживает группу в продуктивном русле

**Когда фасилитация эффективна**: Аудитория с предварительным опытом, задачи на интеграцию знаний, развитие критического мышления. Уровни 4-6 Блума (анализ, оценка, создание).

**Когда неэффективна**: Полностью новый предмет без базовых знаний (нужен сначала Докладчик). Тест: «Кто говорит >70% времени?» — если наставник, это лекция, а не разбор.

## Квалификация

- Мастер (опытный практик) или реформатор (разработчик методов)
- Опытный глаз: видит проблемы, невидимые автору
- Способен вести разбор, а не только «проверять»

## Где действует

- **Практикум** (MIM.FMT.002) — коррекция тренировки
- **Резидентура** (MIM.FMT.003) — review шедевра
- **Разбор** (MIM.FMT.004) — все программы развития

## Чем НЕ является (Режим 1)

- Не докладчик (не читает лекции — для этого MIM.R.002); *в Режиме 2 предметная функция входит через связку (MIM.R.011 подроль Преподаватель-предметник) — см. §Режим 2*
- Не начальник (не выдаёт задания — проект свой)
- Не экзаменатор (замер ≠ экзамен, MIM.D.004)
- Не ментор (MIM.R.006) — наставник работает на разборах (оперативно), ментор — персональная долгосрочная поддержка (years)

## Принцип (Режим 1)

> «Развитие бесконечно: опытный глаз наставника увидит проблемы даже в хорошей работе.»

## Режим 2 — Always-on диагноз+рекомендация (чат, 1:1)

> Заведён по РП-498 (2026-07-20). Human-facing точка опоры «прямо сейчас» между плановыми доставками персонального руководства (РП149) — не по расписанию, а в любой момент, когда пилот описывает своё текущее состояние своими словами в чате.

### Состав связки (RoleRelationStructure, FPF A.2.7)

Режим 2 реализуется НЕ одной сущностью, а маршрутизацией внутри одного ответа между четырьмя ролями-компонентами — закрытый, поимённо обоснованный список (не открытый набор «по требованию», см. АрхГейт ниже):

| Роль-компонент | Метод | Что даёт в ответе |
|----------------|-------|--------------------|
| Диагност (DP.ROLE.042 / MIM.R.009) | Формальная диагностика cp-состояния | Диагноз: что сейчас происходит с человеком |
| Навигатор (MIM.R.007) | Адаптация + смысловая навигация + калибровка мотивации ВНУТРИ роли ученика | Рекомендация: что делать дальше и зачем, место на карте развития |
| Преподаватель-лидер (MIM.R.011) | Системное лидерство | Постановка в саму роль ученика — когда человек её сейчас не играет |
| Преподаватель-предметник (см. курс «Инженерия личности») | Предметная экспертиза, поиск ошибки мышления | Объяснение по предмету — **grounding-инвариант обязателен**: только со ссылкой на конкретный метод из PACK-personal, никогда из общих знаний модели |

### Функции (Режим 2)

1. **Принимает свободный текст** о текущем состоянии человека в любой момент (не по расписанию, не по команде)
2. **Маршрутизирует** между ролями-компонентами внутри одного ответа — видно в трейсе, какая часть ответа от какой роли (не даёт связке «протечь» в отдельную нерегламентированную сущность)
3. **Честно деградирует** при нехватке данных — явное «не хватает контекста» или универсальный (неперсонализированный) ответ, без ложной персонализации
4. **Не хранит raw-текст** дольше сессии одного ответа; маскирует перед любым логом

### Отличие от Режима 1

| Режим 1 (плановый разбор) | Режим 2 (always-on чат) |
|---|---|
| Группа, по расписанию практикума/резидентуры | 1:1, в любой момент |
| Метод — фасилитация (вопросы, не ответы) | Метод — диагноз + прямая рекомендация |
| Разбирает уже сделанную работу | Реагирует на текущее состояние человека |
| Один исполнитель (мастер/реформатор) | Связка 4 ролей, маршрутизация в одном ответе |

### Архитектурное решение и обоснование

АрхГейт (РП-498, пересмотрен 2026-07-20 после первого прохода 2026-07-20): связка ролей через `RoleRelationStructure@BoundedContext` (FPF A.2.7) принята как единственный вариант, проходящий вето-фильтр — среди сравнивавшихся: отдельная новая роль, расширение одной роли целиком, «должность с открытым набором ролей по требованию» (все отклонены — либо каскадный blast radius на downstream-потребителей, либо анти-паттерн F.14 Hybrid/Prestige Role Shortcut). Полная запись решения: `DS-my-strategy/inbox/WP-498/WP-498.md`, `DS-my-strategy/decisions/2026-07/`.

**Явно принятый риск (Безопасность ⚠️/❌, зафиксировано пилотом с обязательной митигацией):**
- Raw-текст пользователя → TTL на сессию ответа + маскирование перед логом (паттерн трейсов РП149).
- Предметная рекомендация (Преподаватель-предметник) → обязательный grounding на конкретный `PD.METHOD.*` из PACK-personal, никогда генерация из общих знаний модели о личном развитии — механизм grounding-гейта проектируется в фазах реализации РП-498.
