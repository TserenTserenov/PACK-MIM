# MIM.M.015 — Evaporating Cloud (EC / Конфликтное облако)

> Формальная структура для разрешения конфликта между двумя необходимыми действиями через поиск скрытых допущений.

## Summary

EC (Evaporating Cloud, «Grounding Cloud», «Conflict Resolution Diagram») — инструмент Thinking Processes для ситуации, когда два действия D и D' оба кажутся необходимыми, но несовместимы. Метод выявляет скрытые допущения в цепи рассуждений и предлагает injection (инъекцию), которая «испаряет» конфликт.

## Структура

```
A (общая цель)
├── B (необходимость 1) ──→ D (действие 1)
└── C (необходимость 2) ──→ D' (действие 2, несовместимо с D)
```

Элементы:
- **A** — общая цель (что оба хотят достичь)
- **B** — необходимость, ведущая к D («чтобы достичь A, нам нужно B»)
- **C** — необходимость, ведущая к D' («чтобы достичь A, нам нужно C»)
- **D** — действие, удовлетворяющее B
- **D'** — действие, удовлетворяющее C, но несовместимое с D
- **Assumptions** — на каждой стрелке (A→B, B→D, A→C, C→D') — скрытые допущения

## Алгоритм

1. Сформулировать D и D' как конкретные **действия** (не ценности/принципы)
2. Найти необходимость B (зачем D?) и C (зачем D'?)
3. Найти общую цель A (что объединяет B и C?)
4. Для каждой стрелки — вербализовать хотя бы 2 допущения явно
5. Найти допущение, которое **ложно или частично ложно** → это точка для injection
6. Сформулировать injection: что нужно сделать иначе, чтобы конфликт испарился

## Quality Gate

EC работает когда:
- D и D' — действия, не ценности («инвестировать X» vs «инвестировать Y», не «гибкость» vs «стабильность»)
- A — реальная общая цель, не объединение D и D'
- На каждой стрелке — ≥2 явных допущения (не «потому что так надо»)

EC не работает (пустая формулировка) когда:
- D и D' — ценности или принципы
- A сформулирован как «и то и другое сразу»
- Допущения одноразовые фразы без конкретики

## Применение в IWE

| Контекст | Как применять |
|----------|---------------|
| **Strategy Session (НЭП §4)** | Два конкурирующих приоритета → EC для выбора injection (что изменить, чтобы снять конфликт) |
| **bottleneck-pick (Шаг 6)** | Два кандидата bottleneck равны по сигналам → EC для выбора |
| **ArchGate** | Два архитектурных варианта с несовместимыми требованиями → EC |
| **WP Gate** | Конфликт «делать РП А или РП Б» при ограниченном бюджете → EC |

```
### EC — конфликтное облако
**A (общая цель):** ...
**B (необходимость 1):** ...  **C (необходимость 2):** ...
**D (действие 1):** ...       **D' (действие 2):** ...

Допущения:
- A→B: [1], [2]
- B→D: [1], [2]
- A→C: [1], [2]
- C→D': [1], [2]

Ложное допущение: [какое и почему]
Injection: [что сделать иначе]
```
