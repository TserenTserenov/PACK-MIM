# MIM.M.030 — Классификатор типа системы

## Описание

LLM-prompt + чек-лист с весами. 7 диагностических вопросов с выбором A/B/C → scoring по трём типам систем (личность / команда / организация). Маршрутизирует к одной из трёх дисциплин программы РР (СИ / СМ / ИЛ).

## Вход

- Запрос субъекта об изменении (свободный текст).
- Опционально: cp-профиль субъекта (из R28) для калибровки.

## Выход

```yaml
system_type: personality | team | organization | ambiguous
scores: {personality: int, team: int, organization: int}
margin: int  # scores[dominant] - scores[second]
recommended_discipline: IL | SM | SI | needs_clarification
```

---

## 7 диагностических вопросов

### В1. «Какого масштаба система, которую вы хотите изменить?»

| Ответ | Описание | Вес |
|-------|----------|-----|
| **A** | Я сам (моё поведение, привычки, мышление) | +3 personality |
| **B** | Моя команда / семья / ближайшее окружение (3-10 человек) | +2 team |
| **C** | Моя организация / компания / сообщество (более 10 человек, есть структура) | +3 organization |

### В2. «Где сейчас лежит корень проблемы — во мне, в отношениях между людьми, или в структуре/процессах?»

| Ответ | Описание | Вес |
|-------|----------|-----|
| **A** | Во мне (я понимаю, что моё поведение создаёт результат) | +3 personality |
| **B** | В отношениях (люди не договариваются, роли не ясны, конфликты) | +3 team |
| **C** | В структуре (процессы разваливаются, масштабирование ломает работающее) | +3 organization |

### В3. «Кто ещё, кроме вас, вовлечён в изменение?»

| Ответ | Описание | Вес |
|-------|----------|-----|
| **A** | Никто, я работаю над собой сам | +3 personality |
| **B** | Конкретные люди (могу назвать имена), мы взаимодействуем регулярно | +3 team |
| **C** | Много людей, которых не знаю лично; изменение касается должностей, не личностей | +3 organization |

### В4. «Какой инструмент ближе по интуиции: практика и рефлексия / роли и договорённости / процессы и метрики?»

| Ответ | Описание | Вес |
|-------|----------|-----|
| **A** | Практика и рефлексия (упражнения, ведение дневника, наблюдение за собой) | +3 personality |
| **B** | Роли и договорённости (RACI, контракты, регулярные встречи команды) | +3 team |
| **C** | Процессы и метрики (workflow, KPI, dashboard'ы, регламенты) | +3 organization |

### В5. «Какой временной горизонт изменения вы видите?»

| Ответ | Описание | Вес |
|-------|----------|-----|
| **A** | Недели (хочу почувствовать сдвиг за месяц) | +3 personality |
| **B** | Месяцы (изменения в команде требуют 3-6 месяцев) | +2 team |
| **C** | Годы (трансформация компании — это долгий цикл) | +3 organization |

### В6. «Что было источником запроса?»

| Ответ | Описание | Вес |
|-------|----------|-----|
| **A** | Внутренний дискомфорт (я недоволен собой) | +3 personality |
| **B** | Внешний конфликт (с коллегой, в команде) | +2 team |
| **C** | Внешнее давление (рынок, регулятор, конкуренты, стейкхолдеры) | +3 organization |

### В7. «Что изменится в первую очередь, если задумка сработает?»

| Ответ | Описание | Вес |
|-------|----------|-----|
| **A** | Мои действия (я начну делать иначе) | +3 personality |
| **B** | Наши взаимодействия (мы начнём договариваться иначе) | +3 team |
| **C** | Наши процессы (документы, регламенты, метрики изменятся) | +3 organization |

## Схема scoring

```python
scores = {"personality": 0, "team": 0, "organization": 0}

for question in [В1, В2, В3, В4, В5, В6, В7]:
    answer = ask(question)            # A | B | C
    type_for_answer, weight = lookup_weight(question, answer)
    scores[type_for_answer] += weight

dominant = max(scores, key=scores.get)
second   = sorted(scores.values(), reverse=True)[1]
margin   = scores[dominant] - second

if margin < 3:
    return {"system_type": "ambiguous", "scores": scores, "margin": margin,
            "recommended_discipline": "needs_clarification"}
elif dominant == "personality":
    return {"system_type": "personality", "scores": scores, "margin": margin,
            "recommended_discipline": "IL"}
elif dominant == "team":
    return {"system_type": "team", "scores": scores, "margin": margin,
            "recommended_discipline": "SM"}
elif dominant == "organization":
    return {"system_type": "organization", "scores": scores, "margin": margin,
            "recommended_discipline": "SI"}
```

---

## Порог неоднозначности и уточняющие вопросы

При `margin < 3` — не выбирать метод. Задать 1-2 уточняющих вопроса. Шаблоны:

- **Если personality + team равны:** «Если бы вы могли изменить только одно — себя или то, как вы взаимодействуете с командой?»
- **Если team + organization равны:** «Изменение касается конкретных людей в команде, или роли (должности), которые они занимают?»
- **Если personality + organization равны:** «Это случай, когда вы как руководитель сами должны измениться, чтобы изменить организацию, или достаточно изменить структуру/процессы независимо от вас?»

После уточнения — пересчитать scoring, повторить проверку margin. Если margin всё ещё < 3 — эскалация к R5 Архитектору IWE.

## LLM-prompt (корень)

```
Ты — классификатор типа системы (MIM.M.030).

Задача: определить, какого типа система требует изменения у субъекта — личность,
команда или организация — и порекомендовать дисциплину программы РР (ИЛ / СМ / СИ).

Алгоритм:
1. Задай 7 вопросов (В1-В7) последовательно.
2. Для каждого ответа начисли вес по таблице.
3. Вычисли scores и margin.
4. Если margin < 3 — задай 1-2 уточняющих вопроса из шаблонов, пересчитай.
5. Верни JSON: {system_type, scores, margin, recommended_discipline}.

Запрещено:
- Выдавать рекомендованную дисциплину при margin < 3 без уточнения.
- Пропускать вопросы (все 7 обязательны).
- Объяснять субъекту веса до завершения диагностики (искажает ответы).

После диагностики передай управление Менеджеру оргразвития (DP.ROLE.063) для
проверки applicability и готовности субъекта (Шаги 1-2).
```

## Метрика и калибровка

Лог каждого вызова в `learning.system_type_diagnostics`:

```yaml
session_id: ...
subject_id: ...
scores: {personality: 9, team: 4, organization: 3}
margin: 5
chosen: personality
discipline: IL
post_hoc_verified: null | true | false  # заполняется post-hoc оператором
```

**Калибровка (период: 10 вызовов):**
- Если ≥30% запросов с `margin < 3` → пересмотр весов или 8-й вопрос.
- Если post-hoc verification показывает классификация ≠ реальный тип системы > 20% — переоформление через BORO-стандарт (MIM.M.029).
