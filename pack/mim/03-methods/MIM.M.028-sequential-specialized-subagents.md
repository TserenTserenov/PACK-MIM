# MIM.M.028 — Последовательные специализированные суб-агенты верификации качества

## Назначение

Метод верификации документа или артефакта с многомерными требованиями качества через последовательность специализированных суб-агентов с контекстной изоляцией.

## Когда применять

- Документ имеет ≥2 независимые оси требований (структурные + педагогические, технические + пользовательские, архитектурные + операционные)
- Одиночный «mega-reviewer» перегружается: либо пропускает ошибки одной оси, либо смешивает критерии
- Требования разных осей имеют явный приоритет (структурные > педагогические)

## Принцип

1. Определить оси требований и их приоритет
2. Для каждой оси назначить специализированный суб-агент со своим чеклистом и ролевым промптом
3. Запустить суб-агентов **последовательно** (не параллельно): ошибки первичной оси должны быть выявлены до проверки вторичной
4. Каждый суб-агент получает только: (а) свой чеклист и (б) проверяемый текст — контекстная изоляция обязательна

## Пример (WP-322 Ф14)

Проверка подраздела персонального руководства:
- **FPF-верификатор** (первичный, Opus): структурные требования — граничные объекты, системная иерархия, G-H-L компоненты FPF
- **Педагог-верификатор** (вторичный, Opus): педагогические требования — activation, transfer test, I-J-K критерии

Результат: чёткие критерии отказа для каждой оси, меньше когнитивной перегрузки, чем у одного mega-reviewer.

## Триггер применения

Верификационная задача, для которой одиночный reviewer получает ≥2 чеклистов разной природы в одном промпте.

## Связи

- Применяется в: `/verify` skill (FMT-exocortex-template), pipeline документов руководств (WP-322)
- Отличие от параллельного запуска: последовательность обязательна, если ошибки первой оси аннулируют вторую проверку
